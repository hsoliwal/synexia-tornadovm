# Component guide: build boundaries and ownership

Source baseline: `859491173b9940a2e4617a37fa799f828e971299`. These are observations of this public fork, not a hardware qualification or a claim of complete API review. See the [inventory and coverage ledger](COMPONENT_INVENTORY.md) for every discovered Maven/JPMS and Java source-package boundary, and [host/device lifecycle](HOST_DEVICE_LIFECYCLE.md) for the reviewed execution path.

## Read the dependency direction first

Applications describe work through `tornado-api`. `tornado-runtime` implements scheduling, compilation and interpretation; the backend modules depend on it and supply device-specific implementation. Native-library modules depend on API/runtime and register providers. Examples, benchmarks, tests and the CPU model consume those facilities. The graph builder, JVM, Graal compiler, native binding and command submission are host-side code; selected compiled kernel or library work executes on the chosen device. A Java package named `cpu` is not sufficient evidence of the execution location.

Evidence: [runtime descriptor](https://github.com/hsoliwal/synexia-tornadovm/blob/859491173b9940a2e4617a37fa799f828e971299/tornado-runtime/src/main/java/module-info.java), [CUDA descriptor](https://github.com/hsoliwal/synexia-tornadovm/blob/859491173b9940a2e4617a37fa799f828e971299/tornado-drivers/cuda/src/main/java/module-info.java), [cuBLAS descriptor](https://github.com/hsoliwal/synexia-tornadovm/blob/859491173b9940a2e4617a37fa799f828e971299/tornado-cublas/src/main/java/module-info.java), and the [lifecycle trace](HOST_DEVICE_LIFECYCLE.md).

## How to use the map

- For applications, start with `TaskGraph`, `ImmutableTaskGraph`, `TornadoExecutionPlan` and native-array types in [the lifecycle guide](HOST_DEVICE_LIFECYCLE.md)
- For a new native-library binding, inspect the provider SPI and descriptor/argument marshalling before changing a factory; a valid service registration alone does not prove compatible argument layout
- For compiler changes, use the backend's declared dependency direction and packages in [the inventory](COMPONENT_INVENTORY.md); individual Graal lowering, LIR and node semantics are still unreviewed
- For the CPU-model experiment, distinguish the host reference executor from the persistent Tornado session and its explicit synchronization methods
- For build, launcher, SDK and test commands, use [BUILD_AND_RUN.md](../BUILD_AND_RUN.md). Those instructions are source-checked, not a receipt that this machine built or executed them
